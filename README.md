# Gomoku Match

一个面向 Botzone 的 15x15 五子棋对弈 Bot，使用 C++ 和 jsoncpp 实现，支持换手规则。当前为单文件实现，核心思路是棋形匹配加加权估值，在已有棋子附近生成候选点并选择综合得分最高的位置落子。

## 功能特性

- 15x15 标准棋盘
- 支持 Botzone `requests` / `responses` JSON 格式
- 支持换手规则，`-1` 表示换手
- 黑棋首手从四角 2x2 开局池中随机选择，降低被换手风险
- 仅在已有棋子周围 2 格范围内生成候选点
- 覆盖活二、眠二、活三、眠三、冲四、活四、连五等基础棋形
- 对双活三、四三、双冲四等组合威胁进行加权

## 依赖与环境

- C++17 或更高版本
- jsoncpp

Botzone 编译环境默认提供 `jsoncpp/json.h`，直接在 Botzone 选择 C++ 语言并提交 `bot.cpp` 即可。

本地编译示例（需要系统已安装 jsoncpp）：

```bash
g++ -std=c++17 -O2 bot.cpp -o bot -ljsoncpp
```

## 输入输出

程序从标准输入读取一行 JSON，并向标准输出写入一行 JSON。

当前轮到黑棋先手时，输入示例：

```json
{"requests":[{"x":-1,"y":-1}],"responses":[]}
```

输出示例：

```json
{"response":{"x":1,"y":1}}
```

当前轮到白棋且黑棋首手已经落子时，输入示例：

```json
{"requests":[{"x":7,"y":7}],"responses":[]}
```

如果选择换手，输出：

```json
{"response":{"x":-1,"y":-1}}
```

## 核心策略

1. 根据历史 `requests` 和 `responses` 恢复棋盘状态，并处理换手。
2. 调用 `exploreNewPoint` 在已有棋子附近生成候选落点。
3. 对每个候选点分别计算己方落子得分和对方落子得分。
4. 综合得分 = 己方得分 + 对方得分 × 1.2。
5. 如果己方存在连五点，直接取胜；如果对方存在连五点，优先防守。

当前换手策略：黑棋首手落在中腹 3~11 区域时选择换手，否则根据首手估值决定是否换手。

## 已知限制与后续优化

- 当前为单层贪心估值，没有搜索树，对需要多步计算的杀棋识别有限。
- 棋形库目前只覆盖了部分常见棋形，带空位冲四、部分活三和边界眠三尚未完整收录。
- 候选点生成和估值权重仍有调优空间。
- 后续可以引入 minimax / alpha-beta 搜索、蒙特卡洛方法或更完整的棋形库来提升棋力。
